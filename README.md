# iGuide HAND Dam Workflow

This repository contains Python scripts for Height Above Nearest Drainage
(HAND) inundation mapping workflow for aging dams. The workflow combines HUC12
watershed analysis with TauDEM hydrologic processing to generate flood
inundation maps.

## Workflow Description

### dam_catchments.py

This script calculates bounding boxes for all HUC12 watersheds downstream from a dam location. Key features include:

- **Dam Location Analysis**: Finds the starting HUC12 watershed containing the dam location
- **Downstream Traversal**: Follows HUC12 connectivity data to identify all downstream watersheds
- **Distance Calculation**: Uses sqrt(area) formula to calculate cumulative distance along the flow path
- **Automatic Termination**: Stops at 100km distance or closed basins (terminal watersheds)
- **Bounding Box Computation**: Calculates spatial bounds in the target raster projection
- **Raster Clipping**: Optionally clips all NHDPlus rasters to the calculated bounding box with optional buffer

The script outputs downstream HUC12 shapefiles, bounding box coordinates, and optionally clipped rasters for efficient processing.

### dam_hand.py

This script implements the HAND (Height Above Nearest Drainage) calculation workflow. Key components include:

- **Data Preparation**: Copies and preprocesses clipped rasters and input files
- **Flow Direction Processing**: Creates flow direction masks and reclassifies ArcGIS D8 to TauDEM encoding
- **TauDEM Integration**: Runs TauDEM tools for pit removal, flow direction, and contributing area calculations
- **HAND Calculation**: Computes Height Above Nearest Drainage using D-infinity distance-down method
- **Stream Network Analysis**: Generates stream networks and processes outlet locations
- **Catchment Processing**: Creates catchment lists for hydraulic analysis
- **Segment Outlets** (optional, `--segment-length`): Generates reach outlets at fixed intervals (e.g. 2 km) along the dam's downstream main stem instead of using a hand-made outlets shapefile

The workflow produces HAND rasters, stream networks, and catchment data required for inundation analysis.

### generate_segment_outlets.py

Places outlet points at fixed along-stream intervals (default 2 km) on the TauDEM D8 main stem below the dam. It traces `p.tif` from the snapped dam outlet (`outlet.shp`) along the dam's stream grid (`src.tif`). Outlets go on the TauDEM network rather than on hydrofabric/NHD flowlines because HAND, `streamnet` and the catchments are all defined on that grid; vector flowlines from another DEM drift off the D8 path. A short last reach (< `--min-segment-length`, default half the segment length) is merged into the reach above. The trace ends at `--max-distance` meters below the dam if given; otherwise just upstream of where it first enters a large lake or reservoir from `--waterbody-path` (NHDPlus HR `NHDWaterbody`; by default the HU4 GDB recorded by `dam_catchments` in `run_info.json`); otherwise at the end of `src.tif`. The stretch below the end gets `DSNODEID = -1` and is left out of `catchlist.csv`. `--confluence-ratio` optionally adds breaks just above major tributary confluences (where contributing area jumps by more than the given fraction). The output has the same schema as the hand-made `Outlets2_utm.shp` (`ID` = 1 for the dam, 0 otherwise), plus `type` and `dist_m` (distance below the dam).

It runs automatically inside `dam_hand` when `--segment-length` is given. It can also run on its own (`uv run dam_outlets --work-dir outputs/mountain_dell --to-crs EPSG:26912`) on an existing `dam_hand` output directory, so you can inspect or edit the outlets in GIS and pass them back through `--outlets-on-reaches`.

**Note:** Reach IDs (`LINKNO` in `net2.shp` / `Id` in `catchlist.csv`) change whenever the outlets change, so `forecast.csv` must be keyed to the IDs from the same run.

### dam_hydroprop.py

This script builds the synthetic rating curve table (`hydroprop.csv`) from the HAND data generated by `dam_hand.py`, using TauDEM `catchhydrogeo`. For each reach and each stage height in `stage.txt` it computes the wetted area, volume, cross-sectional area, wetted perimeter, hydraulic radius, and Manning discharge. The table depends only on terrain and reach hydraulics, so it is computed once per HAND run.

### dam_inundation.py

This script maps inundation depth for a flow scenario (`forecast.csv`) using `hydroprop.csv` and TauDEM `inundepth`. It validates the forecast against the reach IDs of the current run and against the rating-curve range. Then it writes an inundation depth raster and a per-reach depth table.

Because the two scripts are separate, you can run inundation for many scenarios without re-running the HAND workflow or the hydraulic properties step.

## Installation and Usage

### Prerequisites

The HAND workflow requires TauDEM 5.4.0 or later. Make sure to install TauDEM and its dependencies if not already installed.

### For End Users

If you just want to use the iGuide HAND workflow tools, you can install them using `uv` (recommended) or `pip`.

#### Option 1: Using uv (Recommended)

1. **Install uv** (if not already installed):

   ```bash
   curl -LsSf https://astral.sh/uv/install.sh | sh
   ```

2. **Create a new project and install iguide-hand**:

   ```bash
   uv init my-dam-analysis
   cd my-dam-analysis
   uv add git+https://github.com/pkdash/iguide-hand.git
   ```

#### Option 2: Using pip

1. **Create and activate a virtual environment**:

   ```bash
   python -m venv venv
   source venv/bin/activate  # On Windows: venv\Scripts\activate
   ```

2. **Install iguide-hand**:

   ```bash
   pip install git+https://github.com/pkdash/iguide-hand.git
   ```

#### Option 3: Quick Testing (No Global Installation)

For quick testing without global installation, you can clone the repository and use `uv run`:

```bash
git clone https://github.com/pkdash/iguide-hand.git
cd iguide-hand
uv sync
uv run dam_catchments --help
```

### Data Setup

The `data/` directory is not in the repository; create it next to the project root. Each dam has its own self-contained folder, `data/<dam>/`, passed as `--dam-dir`. It holds the dam's inputs and the NHDPlus HR HU4 dataset for the HU4 that contains the dam.

#### Dam inputs

- **Dam location**: `dam_location.shp`, a point shapefile. A single `*dam_location.shp` (for example `beach_city_dam_location.shp`) also works, or you can pass `--dam-shapefile` (a bare filename is looked up in the dam folder).
- **Stage data**: `stage.txt`, the stage heights (m) used to build the rating curves.
- **Forecast data** (optional): `forecast.csv` with per-reach discharge (`Id, flow_m3s`), keyed to the reach IDs of the current `dam_hand` run. You can supply it later through `dam_inundation --forecast-file`.
- **Outlet locations** (optional): `Outlets2_utm.shp`, defining the reach outlets. It is not needed when `dam_hand` runs with `--segment-length`.

#### NHDPlus HR dataset for the dam's HU4

Download the NHDPlus HR geodatabase and raster set for the HU4 that contains the dam, and unzip both into the dam folder. `dam_catchments` finds them automatically:

- **HU4 geodatabase**: the single `*.gdb` with a `WBDHU12` layer, directly in the dam folder or one subfolder down, for example `NHDPLUS_H_1602_HU4_20220412_GDB/NHDPLUS_H_1602_HU4_20220412_GDB.gdb`. It provides the `WBDHU12` layer for the downstream HUC12 walk, and the `NHDWaterbody` layer for the lake/reservoir stop. Other geodatabases, such as `elev_source.gdb` in the raster folder, are ignored.
- **HU4 raster folder**: the single subfolder containing `hydrodem.tif`, for example `NHDPLUS_H_1602_HU4_20220412_RASTER/` (it also holds `fdr.tif`, `elev_cm.tif`, and so on).

To use NHDPlus data stored elsewhere, pass `--huc12-gdb` and `--raster-dir` to `dam_catchments`. A bare name (no directory part) is looked up in the dam folder; any other relative path, including `./name`, is taken from the current directory. You can also symlink the folders into the dam folder.

#### Example directory structure

```text
data/
├── mountain_dell/
│   ├── mountain_dell_dam_location.shp
│   ├── stage.txt
│   ├── forecast.csv
│   ├── Outlets2_utm.shp
│   ├── NHDPLUS_H_1602_HU4_20220412_GDB/
│   │   └── NHDPLUS_H_1602_HU4_20220412_GDB.gdb
│   └── NHDPLUS_H_1602_HU4_20220412_RASTER/
│       ├── hydrodem.tif
│       └── ...
└── beach_city_dam/
    ├── beach_city_dam_location.shp
    ├── stage.txt
    ├── NHDPLUS_H_0504_HU4_GDB/      # Beach City Dam is in HU4 0504 (Muskingum)
    └── NHDPLUS_H_0504_HU4_RASTER/
```

By default, every stage writes to `outputs/<dam>/`, named after the `--dam-dir` folder, so runs for different dams do not overwrite each other.

## Running in JupyterHub

`notebooks/dam_inundation_pipeline.ipynb` runs the whole pipeline, from a dam's latitude/longitude to inundation depth maps, with plots after each stage. Mountain Dell Dam is the worked example. To run another dam, edit the *Parameters* cell (`DAM_NAME`, `DAM_LAT`, `DAM_LON`) and run all cells. The notebook uses `src/dam_setup.py` to:

- find the HU4 that contains the dam;
- download that HU4's NHDPlus HR GDB and raster zips from the USGS National Map bucket (the raster zip is 1–6 GB);
- write the dam point shapefile and a default `stage.txt` into `data/<dam>/`.

Existing files are kept. Set `NHD_CACHE_DIR` to a shared folder (e.g. `data/`) so dams in the same HU4 download the data only once.

TauDEM (>= 5.4.0) and MPI must already be installed; set `TAUDEM_PATH` in the notebook. One-time setup from the repo root:

```bash
uv sync --group notebook
uv run python -m ipykernel install --user --name iguide-hand --display-name "Python (iguide-hand)"
```

Then open the notebook in JupyterHub and select the **Python (iguide-hand)** kernel.

## Detailed Execution Commands

Follow this sequence for a complete analysis. The examples use Mountain Dell Dam; for another dam, change `--dam-dir`.

### 1. Computing HUC12 Bounding Box and Clipping HUC12 Rasters

Calculate downstream HUC12s and prepare clipped datasets to optimize performance.

```bash
uv run dam_catchments --dam-dir data/mountain_dell
```

For all options, run `uv run dam_catchments --help`.

This command will:

- Calculate the bounding box for all HUC12 watersheds downstream from the dam location
- Clip all NHDPlus rasters to the calculated bounding box
- Add a 4000-meter buffer around the bounding box before clipping
- Save clipped rasters to `outputs/<dam>/clipped/`
- Generate processing reports and downstream HUC12 shapefiles
- Record the inputs in `outputs/<dam>/run_info.json`; `dam_hand` and `dam_outlets` read the HU4 GDB path from this file

The downstream walk stops at whichever comes first:
- `--max-distance` (default 100 km);
- a closed or terminal basin;
- the edge of the HU4 GDB.

Only one HU4 is supported. If the river leaves the HU4 before the distance limit, the script logs a prominent warning, and the domain is cut off at the HU4 boundary. The stop reason is printed and recorded in `processing_report.txt`. If the dam is more than 1 km from every HUC12 in the GDB, the script stops with an error, because the GDB is for a different HU4 than the dam.

**Arguments:**

- `--dam-dir` (required): Per-dam input directory.
- `--dam-shapefile`: Dam location shapefile; a bare filename is looked up in `--dam-dir` (default: found in `--dam-dir`).
- `--huc12-gdb`: NHDPlus HR HU4 geodatabase containing the dam; a bare name is looked up in `--dam-dir` (default: found in `--dam-dir`).
- `--raster-dir`: NHDPlus HR HU4 raster directory to clip; a bare name is looked up in `--dam-dir` (default: found in `--dam-dir`).
- `--ref-projection-raster`: Reference raster for the target projection (default: `<raster-dir>/hydrodem.tif`).
- `--max-distance`: Maximum downstream distance in km (default: 100).
- `--buffer`: Extension distance (meters) around the bounding box (default: 4000).
- `--output-dir`: Directory for output files (default: `outputs/<dam>`).
- `--clipped-dir`: Subdirectory for clipped rasters within `--output-dir` (default: `clipped`).
- `--no-clip-rasters`: Only compute the bounding box.

**Outputs:**

- `outputs/<dam>/downstream_huc12s_from_dam.shp`: Shapefile of identified HUC12s.
- `outputs/<dam>/bounding_box_coordinates.txt`: CRS and coordinate bounds.
- `outputs/<dam>/processing_report.txt`: Log of the catchment analysis, including the stop reason.
- `outputs/<dam>/run_info.json`: Input paths used by later stages.
- `outputs/<dam>/clipped/`: Directory containing trimmed NHDPlus rasters.

### 2. HAND Calculation Workflow

Generate the Height Above Nearest Drainage (HAND) raster using TauDEM tools.

```bash
uv run dam_hand \
  --taudem-path /usr/local/bin \
  --dam-dir data/mountain_dell
```

`dam_hand` reads clipped rasters from `outputs/<dam>/clipped` and writes to `outputs/<dam>`. It reads the dam shapefile, `stage.txt`, `forecast.csv` and the outlets shapefile directly from `--dam-dir` (no subfolders).

To generate 2 km reach outlets instead of using `Outlets2_utm.shp`:

```bash
uv run dam_hand --taudem-path /usr/local/bin --dam-dir data/mountain_dell --segment-length 2000
```

For all options, run `uv run dam_hand --help`.

This command will:

- Copy clipped rasters and input files to the working directory
- Process flow directions and elevation data
- Run TauDEM hydrologic analysis tools
- Calculate HAND (Height Above Nearest Drainage) values
- Generate stream networks and process outlet locations
- Create catchment lists for hydraulic analysis

**Arguments:**

- `--taudem-path`: Directory containing TauDEM executable binaries.
- `--dam-dir` (required): Per-dam input directory.
- `--dam-shapefile`: Dam location shapefile; a bare filename is looked up in `--dam-dir` (default: found in `--dam-dir`).
- `--output-dir`: Directory to save HAND results (default: `outputs/<dam>`).
- `--clipped-dir`: Folder containing clipped rasters from step 1 (default: `<output-dir>/clipped`).
- `--dam-move-distance`: How far, in cells, the dam point may move down its flow path to reach the stream grid (default: 200). If it does not reach a stream, for example because the dam coordinate lies in the reservoir or on the embankment, a prominent warning is logged: the main stem would then start on a hillslope path. Fix the dam point or raise this value. A warning is also logged if the snapped point lies inside an NHDPlus lake or reservoir. The DEM is flat there, so the route TauDEM takes across the reservoir may leave by the wrong side instead of through the dam. Put the dam point on the channel just below the embankment; NID coordinates often fall in the reservoir.
- `--outlets-on-reaches`: Name of outlets shapefile in `--dam-dir`
  (default: Outlets2_utm.shp). Ignored when `--segment-length` is set.
- `--segment-length`: Generate outlets every N meters along the dam's main
  stem (e.g. 2000) instead of reading `--outlets-on-reaches`.
- `--min-segment-length`: Shortest generated reach in meters; shorter pieces
  are merged (default: half of `--segment-length`).
- `--confluence-ratio`: Also break generated reaches above confluences where
  contributing area grows by more than this fraction, e.g. 0.2 (default: off).
- `--waterbody-path`: With `--segment-length`, NHDPlus HR GDB whose
  `NHDWaterbody` layer ends the main stem just upstream of the first lake or
  reservoir (FType 390/436) of at least `--min-waterbody-area` km² (default:
  the GDB recorded by `dam_catchments` in `run_info.json`, else the GDB in `--dam-dir`). Waterbodies
  within 500 m of the dam (its own reservoir) are ignored. If no default is
  available, or the GDB has no
  waterbodies near the main stem, the main stem runs to the end of `src.tif`
  with a warning; a `--waterbody-path` you pass explicitly must exist.
- `--min-waterbody-area`: Smallest lake/reservoir in km² that ends the main
  stem (default: 10).
- `--max-distance`: With `--segment-length`, end the main stem this many
  meters below the dam instead. Overrides the waterbody stop.
- `--min-slope`: Smallest believable reach slope (default: 1e-5). See
  [Flat reaches](#flat-reaches) below.
- `--stream-threshold`: Contributing-area threshold in cells for the TauDEM
  stream grid (default: 10000, about 1 km² at NHDPlus HR's 10 m cells).
- `--move-outlet-distance`: Max distance in cells that `moveoutletstostreams`
  moves the reach outlets (default: 3000).
- `--manning-n`: Manning's n for every reach in `catchlist.csv` (default: 0.05).
- `--np`: Number of MPI processes for TauDEM (default: 4). `streamnet` reach IDs
  (`LINKNO`) depend on it, so keep it fixed when reusing a `forecast.csv`.

**Outputs:**

- `outputs/<dam>/hand.tif`: Height Above Nearest Drainage raster.
- `outputs/<dam>/w2.tif`: Catchment raster.
- `outputs/<dam>/catchlist.csv`: List of catchment properties.
- `outputs/<dam>/slp.tif`: Slope raster.
- Various intermediate files generated by TauDEM tools.

#### Flat reaches

A reach's slope in `catchlist.csv` drives its rating curve through Manning's equation. TauDEM `streamnet` computes it as the reach's end-to-end drop on the pit-filled DEM (`fel.tif`) divided by its length. Pit filling leaves flat stretches, so a reach that falls inside one can get a drop of zero even where the river clearly slopes. With a near-zero slope, Manning's equation needs an unrealistically large depth to carry the flow. Short reaches (`--segment-length`) are the most exposed, and because the reach boundaries move with the outlets, a rerun can move the problem to a different reach.

When a reach's slope is below `--min-slope`, `dam_hand` uses the slope of a longer stretch of the main stem instead. It starts with the reach plus one reach upstream and one downstream: the total drop divided by the total length. If that is still below `--min-slope`, it adds one more reach on each side, and so on. Only if the whole main stem is flatter than `--min-slope` is the slope set to `--min-slope`. A warning names each reach adjusted and the slope it now has. Reaches at or above `--min-slope` keep their own slope.

Examples with 2 km reaches at 4000 m³/s:

| Dam | Reach | Own slope | Slope used | Water level before / after |
|---|---|---|---|---|
| Quail Creek | 26 | 0 (zero drop over 2 km) | 2.2e-3 over 6 km | 35.4 m / 8.8 m (neighbours 11.0 m and 8.8 m) |
| Mountain Dell | 4 | 5e-6 | 1.5e-4 over 6 km | 8.7 m / 4.1 m (neighbours 8.5 m and 5.2 m) |

"Before" is the old behaviour, which clamped the slope to `--min-slope`. No other reach changed.

### 3. Hydraulic Properties (Synthetic Rating Curve)

Build the per-reach hydraulic properties table from the HAND outputs. Run this once per `dam_hand` run.

```bash
uv run dam_hydroprop \
  --taudem-path /usr/local/bin \
  --dam-dir data/mountain_dell
```

`--dam-dir` only picks the default `--output-dir` (`outputs/<dam>`). Every file flag defaults to a path inside `--output-dir`. Run `uv run dam_hydroprop --help` to see them all.

This command will:

- Validate `stage.txt`: values must be numeric, > 0, and strictly increasing. A non-numeric header line is skipped.
- Run TauDEM `catchhydrogeo` to compute, for every reach and stage height, the wetted area, volume, cross-sectional area, wetted perimeter, hydraulic radius, and Manning discharge.
- Log the largest discharge each reach can map (its discharge at the top stage).

**Arguments:**

- `--taudem-path`: Directory containing TauDEM executable binaries.
- `--dam-dir`: Per-dam input directory; sets the default `--output-dir` to `outputs/<dam>`.
- `--output-dir`: Directory with the `dam_hand` outputs (default: `outputs/<dam>` with `--dam-dir`, else `outputs`). It is also the default location of every file below.
- `--hand-raster`, `--catch-raster`, `--catchlist`, `--slope-raster`: Inputs from `dam_hand` (defaults `hand.tif`, `w2.tif`, `catchlist.csv`, `slp.tif`).
- `--stage-file`: Stage heights in metres, one per line (default `stage.txt`). For dam-break floods, extend the stages high enough that the top stage's discharge exceeds the expected peak flow.
- `--hydroprop-file`: Output table (default `hydroprop.csv`).
- `--np`: Number of MPI processes (default 4).

**Outputs:**

- `outputs/<dam>/hydroprop.csv`: Hydraulic properties table (synthetic rating curves).

### 4. Inundation Mapping

Generate inundation depths for a flow scenario. You can run this step many times against one `hydroprop.csv`, once per forecast.

```bash
uv run dam_inundation \
  --taudem-path /usr/local/bin \
  --dam-dir data/mountain_dell \
  --forecast-file data/mountain_dell/forecast.csv \
  --inundation-raster outputs/mountain_dell/inundepth_peak.tif \
  --depth-table outputs/mountain_dell/depths_peak.csv
```

This command will:

- Validate the forecast file against the contract below. Missing columns, non-integer or duplicate IDs, or missing flows cause an error.
- Check the forecast reach IDs against `catchlist.csv`. It warns about unknown or unforecast reaches, and stops with an error if no IDs match.
- Warn when a forecast flow exceeds a reach's rating-curve maximum. In that case `inundepth` caps or extrapolates the stage and under-predicts depth, so add higher stages to `stage.txt` and re-run `dam_hydroprop`.
- Run TauDEM `inundepth`.

**Forecast file contract (`forecast.csv`):** a CSV with a header and one row per reach:

```text
Id, flow_m3s
1,4000
14,4000
```

- `Id`: Integer reach ID, equal to `Id` in `catchlist.csv` (`LINKNO` in `net2.shp`) from the **same** `dam_hand` run.
- `flow_m3s`: Discharge in m³/s.

Whitespace after commas is allowed, and extra columns are ignored. A script that generates forecasts can import `load_forecast`, `validate_forecast_ids`, and `validate_rating_curve_range` from `dam_inundation` to check its output.

**Arguments:**

- `--taudem-path`, `--output-dir`, `--np`: As for `dam_hydroprop`.
- `--hand-raster`, `--catch-raster`: Inputs from `dam_hand` (defaults `hand.tif`, `w2.tif`).
- `--forecast-file`: Forecast flows. A bare filename is looked up in `--dam-dir`; any other path is relative to the current directory (default `forecast.csv` in the output dir).
- `--hydroprop-file`: Table from `dam_hydroprop` (default `hydroprop.csv`).
- `--catchlist`: Reach list used for the ID check (default `catchlist.csv`).
- `--inundation-raster`, `--depth-table`: Outputs (defaults `inundepth.tif`, `depths.csv`).

**Outputs:**

- `outputs/<dam>/inundepth.tif`: Flood inundation depth raster.
- `outputs/<dam>/depths.csv`: Per-reach summary of flow, stage depth, inundated area, and inundation ratio.
